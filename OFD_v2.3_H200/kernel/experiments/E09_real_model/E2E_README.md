# Full-model online decode experiment

Protocol: `e2e_protocol.json`. Run the committed source from the repository root with `python kernel/tools/run_e09_e2e.py`; it saves separate online-cache correctness/model-smoke and full-sweep directories under `kernel/results/E09_model_decode_e2e/`. Smoke failure blocks the full sweep. Timing/results are observational; no speedup is required to complete the matrix.

The complete Qwen3.8-27B language decoder runs on each case, including unchanged Gated DeltaNet, FFN and LM head. Model weights remain FP16. There are 16 full-attention layers; all 48 linear-attention layers stay native. P/K/V/KV all use packed INT4 for both KV tensors: P has no rotation, K rotates K/query, V rotates V/output, KV rotates both. K and V flags can differ independently at any layer. These flags are not per-layer FP16/INT4 mixed precision.

Controls: original FP16 SDPA with preallocated dense KV (`NATIVE`), matched split/paged FP16 (`FP16`), all-P, all-KV, then a mixed policy. Dense cache replacement is checked against the unmodified native cache in smoke. FP16 paged and INT4 use the same page table and scheduling principles. Report comparisons against both FP16 controls: speedup against the original SDPA path alone does not attribute the gain to compression if paged FP16 already gives that gain.

Calibration measures 4L=64 one-layer perturbations around all-P using the complete model, three rounds on each of prose/code (384 measurements). The combined speed policy is fixed before held-out multi-domain evaluation and context/batch crossover. This does not search all 4^16 policies or prove a global optimum.

Prefill and cache conversion are untimed. New decode KV is appended to its actual resident representation inside timing, including K/V FWHT and quantization where selected. Full-attention FP16 shadows are removed in INT4 cases; reusable templates are on CPU. Inputs, positions, lengths, masks, event objects and workspaces are prepared first. Main latency and throughput use synchronized wall time after warmup, with GPU event time recorded separately. CPU sampling and server scheduling are excluded. Quality diagnostics use actual policy-conditioned model logits after decode, with fixed teacher-forced inputs.

The observed runtime currently logs Gated DeltaNet/causal-convolution reference fallbacks because the optional fast-path packages are absent. This common unchanged portion can limit or mask attention-policy gains; these measurements must not be described as comparisons against an optimized production serving stack. The raw run.log preserves this information. Storage-exact quantizer validation preserves the existing torch CUDA scalar-division semantics at half-integer rounding boundaries.

Case/shape OOM and host-template limits are saved separately. These setup limits are not a proof of maximum INT4 serving residency. Raw CSV records exact policies, environment/source is in MANIFEST, and data IDs/revisions/token checksums are in data_manifest. `python kernel/tools/analyze_e09_e2e.py RUN_DIRECTORY` generates paired native/paged comparisons, the complete-model 4L table and observed crossover points; partial runs remain labeled incomplete.
